# Project: Apocalypse — сайт

Статический сайт сообщества: лендинг, правила, состав администрации, заявки, поддержка проекта и живой мониторинг игровых серверов.

Без сборки и фреймворков — чистые HTML, CSS и JS. Хостится бесплатно на GitHub Pages.

```
index.html          главная + мониторинг серверов
rules.html          правила Discord, SCP:SL и Minecraft
staff.html          структура администрации
apply.html          заявки: набор, жалобы, апелляции, доступ
donate.html         поддержка проекта
data/site.json      ← ВСЁ, что нужно менять: адреса, ссылки, состав, привилегии
data/status.json    статус серверов, обновляется автоматически
assets/css/style.css
assets/js/main.js
scripts/fetch_status.py        опрос серверов
.github/workflows/status.yml   запуск опроса раз в 10 минут
```

## Что заполнить перед публикацией

Всё в одном файле — `data/site.json`. Ищи слово `ЗАМЕНИ`:

| Поле | Что вписать |
|---|---|
| `project.discord_invite` | Постоянная ссылка-приглашение в Discord |
| `servers[0].address` | Адрес SCP:SL сервера с портом |
| `servers[0].scpsl_account_id` | ID аккаунта из личного кабинета SCP:SL |
| `servers[1].address` | Адрес Minecraft сервера |
| `donate.links[].url` | Ссылки DonationAlerts и Boosty |

Текст правил живёт прямо в `rules.html` — это обычный текст между тегами, правится без знания HTML. Состав администрации, привилегии и заявки берутся из `site.json` и рисуются автоматически.

Пока поля не заполнены, сайт работает: карточки серверов показывают «нет данных» и подсказку, чего не хватает, а блок доната — что ссылки не заданы.

## Мониторинг серверов

Статус собирается **не в браузере**, а в GitHub Actions. Причина простая: API SCP:SL требует секретный ключ, и в клиентском JS его держать нельзя — его увидит любой, кто откроет исходник страницы. Поэтому:

1. Раз в 10 минут GitHub запускает `scripts/fetch_status.py`
2. Скрипт опрашивает серверы и пишет `data/status.json`
3. Если что-то изменилось — коммитит файл в репозиторий
4. Сайт читает готовый `status.json` как обычный статический файл

Чтобы заработал SCP:SL, добавь ключ в **Settings → Secrets and variables → Actions → New repository secret**:

- Имя: `SCPSL_API_KEY`
- Значение: ключ из личного кабинета SCP:SL

Minecraft опрашивается через публичный `mcsrvstat.us` и ключа не требует.

Проверить вручную, не дожидаясь расписания: вкладка **Actions → Обновить статус серверов → Run workflow**.

Локально:

```powershell
cd C:\Users\Mr_Zhorik\apocalypse-site
python scripts/fetch_status.py
```

**Две особенности GitHub Actions, о которых стоит знать:** расписание может задерживаться на несколько минут при нагрузке, а если в репозиторий 60 дней не было коммитов — GitHub отключает cron и его нужно включить руками в разделе Actions.

## Discord Activity

`activity.html` — компактная панель для запуска прямо в голосовом канале Discord: статус обоих серверов, адреса с кнопкой копирования и ссылки на правила, заявки и состав. Обновляется сама раз в минуту.

Полный сайт тоже можно открыть активностью, но он рассчитан на широкий экран, а окно активности маленькое — поэтому сделана отдельная страница. Если захочешь наоборот, в настройках приложения укажешь корень вместо `/activity.html`.

### Шаг 1. Положить SDK в репозиторий

Discord не покажет активность, пока страница не вызовет `ready()` из Embedded App SDK. Загружать SDK со стороннего CDN прямо в браузере нельзя — Discord режет такие запросы по CSP. Поэтому файл кладётся в репозиторий:

```powershell
cd C:\Users\Mr_Zhorik\apocalypse-site
npm install
npm run vendor-sdk
```

Пакет не собран в один файл: `index.mjs` весит меньше килобайта и подтягивает ещё около семидесяти модулей относительными путями. Поэтому в `assets/js/vendor/embedded-app-sdk/` копируется вся папка `output` целиком — примерно 450 КБ. Для GitHub Pages это нормально.

Папка `vendor/` намеренно **не** в `.gitignore`: без неё активность на GitHub Pages не запустится.

Без SDK панель не падает — работает как обычная страница и пишет внизу, что файлы не найдены.

### Шаг 2. Включить Activities

В [Developer Portal](https://discord.com/developers/applications) открой своё приложение (то же, что и бот):

1. **Activities → Settings** → включи **Enable Activities**. Автоматически появится команда запуска «Launch».
2. **Activities → URL Mappings** → добавь маппинг:
   - **Prefix:** `/`
   - **Target:** `ТВОЙ_НИК.github.io/apocalypse-site`
3. Скопируй **Application ID** со страницы General Information и впиши его в `data/site.json` в поле `discord_client_id`.

### Шаг 3. Запуск

Зайди в голосовой канал → иконка ракеты → выбери приложение. Активность откроет `activity.html` через прокси Discord.

### Почему это работает на статике

Discord пропускает весь трафик активности через свой прокси, и обращения к чужим доменам блокируются, если не прописаны в URL Mappings. Нашей панели это не мешает: она читает только `data/status.json` с того же адреса, а сам опрос игровых серверов происходит заранее в GitHub Actions. Если бы статус запрашивался из браузера напрямую у `mcsrvstat.us`, внутри Discord он бы не работал без отдельного маппинга.

Единственное, чего статика не умеет — авторизации пользователя через `authenticate()`: для обмена кода на токен нужен бэкенд. Панели это не нужно, она ничего не знает о том, кто её открыл, и не должна.

## Почему нет форм обратной связи

Статический сайт не может принимать заявки сам — для этого нужен сервер. Вариант «отправлять прямо в Discord через вебхук из браузера» не годится: адрес вебхука будет лежать в открытом JS, и любой желающий сможет спамить им в канал.

Поэтому страница заявок объясняет требования и ведёт в Discord, где для этого уже есть форумы с жалобами и апелляциями. Если позже захочется настоящих форм — нужен переезд на Vercel или Netlify с серверной функцией, разметка при этом сохранится.
